# 需求与验收

## 用户与目标

内容团队需要识别待处理素材，审核内容风险，核对发布时间，形成可供人工确认的排期草稿。项目只保存草稿，不连接真实发布渠道。

## 输入与输出

输入是一条或多条素材请求，每条包含素材 ID、要求时段和是否为硬性要求。素材元数据、审核规则、已有排期和候选时段由本地合成数据提供。批量请求按顺序逐项处理。

每项结果包含审核状态、风险原因、要求与建议时段、确认状态、草稿保存状态及运行记录；工具失败或达到上限时说明未完成原因。

## 验收标准

| 场景 | 预期结果 |
| --- | --- |
| 正常排期 | 审核通过、时段可用，保存草稿 |
| 信息缺失 | 指出缺失项，不保存草稿 |
| 规则风险 | 返回风险原因，阻断高风险素材 |
| 时段冲突 | 查询备选时段；更改要求时标记待确认，或请求确认后停止 |
| 重复提交 | 同一有效请求返回已有草稿，不产生重复记录 |
| 保存失败 | 明确返回失败或未完成，不虚报保存成功 |

硬性发布时间未经用户同意不得变为已确认安排；草稿和真实发布是不同状态。每项任务设置模型轮次与工具调用上限。评估证据见 [评估文档](03-evaluation.md)。
